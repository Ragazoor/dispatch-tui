One board for all your work

Dispatch is a kanban board in your terminal. Every piece of work is a task card in one of four columns: Backlog, Running, Review and Done. You move with h j k l or the arrow keys. Enter opens a task's details. ? lists every key.

Agents do the work

Press Space on a Backlog task and dispatch sends a Claude Code agent to do it. The agent gets its own git worktree (<repo>/.worktrees/<id>-<slug>) and its own tmux window, so your checkout stays clean and many agents can run side by side. Space on a running task jumps to its window. Your tmux prefix then Space jumps back to the board.

Cards move themselves

You rarely set a status by hand. Hooks tell the board when an agent starts, stops or gets blocked. The Running and Review columns are split into sections, called sub-statuses, so the cards that need you sit at the top:

  • Running: conflict, crashed, stale (no activity for a while), needs input (the agent is waiting for you), active.
  • Review: conflict, pr closed, pr unreachable, changes requested, approved, awaiting review, then parked, changes requested by me and approved by me.

z folds a section away when you do not want to see it.

Epics keep a huge backlog in order

An epic groups tasks, and it can hold other epics. An epic's card shows up in every column where it has work, so you see its spread at a glance. Space steps into it, q steps out, Q goes straight back to the top. Inside an epic, U turns on auto-dispatch: when one subtask finishes, the next one starts by itself, on a branch that already holds the work before it.

Work packages cut across epics

An epic says what the work is. A work package says what you are working on now, such as this week's release or an on-call week. It links to tasks and epics wherever they live in the tree. It has no status of its own: an item is done when the item is done. Space on a package card opens it as its own board.

Finishing a task

When an agent is done, the card moves to Review. You (or the agent) run the /wrap-up skill in its session. It commits the work and either rebases it onto the base branch or opens a draft pull request. Once a pull request exists, the board follows its review state on GitHub.

What agents use behind the scenes

  • MCP tools. Dispatch runs an MCP server, so agents are full users of the board. They can read and create tasks, epics and work packages, and dispatch more agents.
  • Skills. Dispatch ships Claude Code skills such as /wrap-up (finish a task), /learnings (the knowledge base) and /retro (what went wrong this session).
  • Knowledge base. Agents record what they learn. The relevant entries go into the next agent's prompt, so the same mistake is not made twice.
  • Feeds. A shell command can pull work onto the board on a schedule, such as pull requests waiting for your review.
