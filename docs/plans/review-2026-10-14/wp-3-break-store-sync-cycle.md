# Break the store↔sync cycle

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** `sync` no longer imports from `store`, and `tests/module_layering.rs` guards that edge.

## Context

This work package addresses findings from the 2026-10-14 code review
(`docs/plans/review-2026-10-14/report.md`, §2 A1, §8 H5). `store` is the
board's handle over `sync`'s rows and reducer transport (18 references
`store→sync`), and `sync` reaches back up for decode helpers, patch/filter
types and three session traits (20 references `sync→store`). The layering
test has no rule for either direction, so the cycle can grow unnoticed.
No behaviour change.

## Findings

### ⚠️ `sync` imports decode helpers from `store` (`src/sync/decode.rs`, `src/sync/rows.rs`)

**Issue:** `crate::store::{bump_decode_fallback, parse_datetime, drop_undecodable}` are called from `sync` (`src/store/decode.rs` defines them; `src/store/mod.rs:13-14` re-exports).

**Fix:** Move `src/store/decode.rs` to `src/sync/decode_support.rs` (or fold into `src/sync/decode.rs`), keep `store` re-exporting `decode_fallback_count` for its public callers.

### ⚠️ `sync` encodes `store`'s patch and filter types (`src/sync/encode.rs`, `src/sync/sdk_connector/queries.rs`)

**Issue:** `encode.rs` converts `crate::store::{EpicPatch, LearningPatch}` to bindings; `queries.rs` takes `crate::store::{LearningFilter, UsageQuery}`.

**Fix:** Either move those four types (and `TaskPatch`, generated by `patch_struct!` in `src/store/mod.rs`) to `src/models/patches.rs`, or move the conversion functions into `store` beside the types. Prefer the first: the types are plain data every layer names.

### ⚠️ `sync::session` re-exports `store` traits (`src/sync/session.rs:38`)

**Issue:** `SyncStore: HostStore + SubscriptionStore + IdentityCredentialStore` pulls three `store` traits into `sync`.

**Fix:** Move the three traits to `src/sync/session.rs` (they describe the connection's identity, not board data) and have `store` implement them from there.

### ⚠️ No layering rule for the edge (`tests/module_layering.rs:21`)

**Fix:** Add `("sync", &["startup", "service", "store"])` once the above is done; the test fails until then, which is the point.

## Changes

| File | Change |
|------|--------|
| `src/store/decode.rs` → `src/sync/decode_support.rs` | Move; update `src/store/mod.rs` re-exports |
| `src/models/patches.rs` (new) | `TaskPatch`, `EpicPatch`, `LearningPatch`, `LearningFilter`, `UsageQuery`, and the `patch_struct!` macro |
| `src/store/mod.rs` | Re-export the moved types so callers keep compiling |
| `src/sync/session.rs` | Own `HostStore`, `SubscriptionStore`, `IdentityCredentialStore` |
| `src/sync/encode.rs`, `src/sync/sdk_connector/queries.rs`, `src/sync/rows.rs`, `src/sync/decode.rs` | Import from `models`/`sync` instead of `store` |
| `tests/module_layering.rs` | Add `store` to `sync`'s forbidden list |
| `docs/module-map.md`, `docs/invariants.md` ("module layering") | Update the rows that cite the moved files |
